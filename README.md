# 借用设备守卫 · dsh-borrowed-device

在公司公用电脑、网吧或朋友的笔记本上临时用 DSH 时，DSH 会把 **API Key、整段会话记录、附件、缓存** 留在 `~/.dsh` 里。这个插件把"别把东西留在别人的机器上"变成三步：**标记 → 干活 → 只清理你自己的**。

## 安装

**源码目录安装（开发机）**：把仓库放在任意位置，DSH → 插件 → 安装本地插件 → 选择仓库目录。目录是链接进来的，改代码后重载插件即可生效。

**打包后带走（公用电脑）**：在仓库里执行

```bash
npm pack
```

把生成的 `dsh-borrowed-device-<版本>.tgz` 拷走；或者直接把整个目录压成 zip，目标机解压后用「安装本地插件」选目录。开发机上 `dist/` 里会有这两种产物，但**不随仓库提交**。

要求 **DSH >= 0.2.1-rc.5**（见 `package.json` 的 `engines.dsh`）；低版本会在安装阶段被告知不满足要求，而不是装上一个不会激活的插件。用完记得把解压出来的目录和安装包一起删掉。


## 核心原则：只删你的，不动别人的

借用别人的电脑时，那台机器的 `~/.dsh` 里很可能已经有**机主自己的**会话、密钥和附件。插件不按目录一刀切，而是**按归属**处理：

| 数据 | 怎么判断"是你的" |
| --- | --- |
| 会话日志、会话投影缓存 | 插件在借用模式下**亲眼看到它被创建**（`session/created`）才计入你的；借用开始前就存在的，一律算别人的 |
| API Key、登录凭据 | 插件在借用模式下**亲眼看到它被写入**（`credentials/reference-updated` / `record-updated`）才算你的 |
| 附件、缓存、临时文件 | 内容寻址、没有归属标记，按**创建时间**判断：本次 DSH 进程启动之后创建的是你的，之前的是别人的 |
| 工作区索引、shell 历史、浏览器数据 | 共享或不属于 DSH，**从不删除**，只在审计里列出来提醒你手动处理 |

审计会把结果分成三类给你看：`mine`（你的，会删）、`foreign`（别人的，绝不会动）、`shared`（共享的，不归插件管）。

**安全兜底**：如果某条数据插件没能确认归属，它默认算"别人的"——宁可少删，也不会误删。

## 它做了什么

| 能力 | 说明 |
| --- | --- |
| 自动进入借用模式 | 在一台没见过的机器（新的 `DSH_HOME`）上首次启动即自动开启；点击「这是我自己的电脑」后永久关闭 |
| 顶栏提醒 | 会话输入框上方常驻一条提示：磁盘上还有没有 key、本机有多少属于你的痕迹、有多少是别人的；带「清理我的」「查看」按钮 |
| 审计 | 列出所有本地痕迹并标注归属和大小，**不读取、不显示密钥值** |
| 密钥定位 | 直接指出 key 是在磁盘上、还是由启动环境提供，并把"怎么才真的不落盘"写清楚（见下方） |
| 清理 | 只删你的会话、投影缓存、附件、缓存、临时文件和凭据，然后重新审计并报告残留 |
| 代理端提醒 | 借用模式下注入系统提示：不把密钥写进文件、不打印 token、不碰机主的数据、收尾时提醒你清理 |

## 界面

会话输入框上方的一条横栏（只在借用模式开启时出现）：

- 红点 + `本机磁盘上仍有 API Key` —— 说明磁盘上有副本，离开前「清理我的」会处理掉
- 如果 key 来自启动环境，会直接显示「密钥来自环境变量，磁盘上没有副本」，红点变绿
- 「清理我的」需要点两次（第二次变成「只删你的数据？」，6 秒不确认自动取消），点之前会先列出要删什么
- 「查看」展开审计列表，`mine` / `foreign` / `shared` 分得清清楚楚
- 横栏还会显示「别人的会话 N」
- 「这是我自己的电脑」把本机标记为可信，横栏消失（见下方"点错了怎么办"）
- 设置 → 通用 里也有一个「借用设备模式」开关，随时可以开/关

## 清理清单（精确到路径）

`%DSH_HOME%` 默认是 `C:\Users\<你>\.dsh`。

### 会删（只限你自己的）

| 类别 | 路径 | 归属判据 |
| --- | --- | --- |
| 会话日志 | `sessions\<工作目录>\<会话id>\` 整个目录（删空的父目录） | 借用中插件看到它被创建 |
| 会话投影缓存 | `storages\session_projcache\sessions\<会话id>.json` | 同上，按会话 id |
| 附件 | `attachments\**`，只删文件、不删目录 | 本次 DSH 进程启动后创建 |
| 缓存 | `cache\**`，只删文件、不删目录 | 本次 DSH 进程启动后创建 |
| 临时产物 | `%TEMP%\dsh-spill-*`、`dsh-subprocess-*`、`dsh-workspace-changes-*`、`dsh-inspect*` | 本次启动后创建，且 30 分钟没有写入 |
| API Key | `.credentials.yaml` 里 `refs` 下你写入的那条 | 借用中插件看到它被写入 |
| 登录凭据记录 | 同文件 `records`（如 `client-connection/browser-session`） | 借用中插件看到它被写入 |
| 工作区条目 | `storages\workspace.json` 里**本次借用新建**的 workspace 条目（通过 registry 按 id 删除） | 借用开始时先快照已有 id，之后新增的才算你的；没拿到快照就一条都不动 |
| shell / git 历史（可选） | `~/.bash_history`、`~/.zsh_history`、`~/.git-credentials`、PSReadLine 的 `ConsoleHost_history.txt` | 默认关闭，需 `shellHistoryOnWipe: true` |

### 明确不会删

- 别人的会话、投影缓存、附件、缓存、临时产物（借用开始前存在的一切）
- 机主自己的 API Key 和登录凭据
- `storages\workspace.json` 里机主原有的 workspace 条目（只移除借用期间新增的）
- 你的代码、文档、下载文件——它们不在上面这些目录里
- 浏览器历史 / 下载 / localStorage、Windows 凭据管理器
- 插件自己的 `.borrowed-device.json`（只有机器指纹和开关，没有任何密钥）

### 删不掉时

正在被 DSH 写着的会话文件如果无法删除，会记进状态文件的 `pendingWipe`，**下次启动 DSH 时补删**。

### 强制全删

`/borrowed wipe confirm all`（或工具参数 `includeUnattributed: true`）会连别人的一起删——只在确认这是一台干净的新机器时用。

## 关于 API Key

DSH 平时把 API Key 明文写在 `~/.dsh/.credentials.yaml`。插件做三件事：

1. **告诉你它在不在**：审计和横栏直接标出「磁盘上有」还是「来自环境变量」。
2. **离开时删掉它**：「清理我的」会把**你写入的**那条从文件里删掉。
3. **真正的保险**：用一次性 / 低额度的 key，离开后到 platform.deepseek.com **吊销**。删本地只能防这台机器，吊销能防所有机器。

### 为什么没有「删掉磁盘副本还能继续用」这个按钮

做过，又删了。原因在运行时里：凭据解析只认**启动时的环境快照**（`dsh-launch-environment` 的 `launchEnvironment`，不可变），`dsh-credentials-local` 的 `inherited()` 只查这份快照。也就是说，**运行中修改 `process.env` 永远不会被看到**——"把 key 挪进内存、删掉磁盘副本、会话继续"在这版 DSH 上做不到。

插件里保留了一个自检（`/borrowed selftest`）用临时 ref 验证这件事，在这台机器上的结论是 `environment-fallback-unavailable`。与其留一个按下去只会回滚、还让人误解的按钮，不如删掉，并把正确做法写清楚。

### 想真正做到"key 不落盘"

**启动 DSH 之前**就把 key 放进环境，DSH 就不会往凭据文件里写：

- 进程环境：启动前设置 `DEEPSEEK_API_KEY=...`，再从同一个终端启动 DSH；
- 或写进 `$DSH_HOME/.env`（属于 `user-env` 层，启动时读取）。

这样启动后横栏会显示「密钥来自环境变量，磁盘上没有副本」，审计里也不会再报 key 在磁盘上。

> 注意：`.env` 本身也是个文件，只是不在 DSH 的凭据文件里；在别人机器上写它同样要记得删。

## 点错了怎么办

「这是我自己的电脑」是可撤销的，按先后有三种方式：

1. **刚点完**：横栏会变成一条确认提示，12 秒内点「撤销」即可恢复。
2. **任何时候**：在输入框输入 `/borrowed on`（或 `/borrowed arm`）。
3. **想用界面**：设置 → 通用 → 「借用设备模式」开关打开。

误点**不会丢数据**：信任操作只是关掉提醒，并不会清空"哪些会话/凭据属于你"的记录，重新打开后归属照旧。只有真正执行清理之后，这些记录才会被清掉。

## 命令与工具

```
/borrowed                    # 状态
/borrowed audit              # 审计（按归属分组）
/borrowed selftest           # 自检：这版运行时能不能做到"不落盘还能用"
/borrowed wipe               # 预览"你的"哪些会被删
/borrowed wipe confirm       # 只删你的
/borrowed wipe confirm all   # 连别人的一起删（仅限确认是干净新机器时）
/borrowed trust              # 这台是我自己的电脑
```

代理工具 `borrowed_device`，动作：`status` `audit` `selftest` `wipe`（必须 `confirm: true`，`includeUnattributed: true` 才是全删）`arm` `trust`。

## 配置

在 `cordis.patch.yml` 里按行 id 覆盖（改完重启生效）：

```yaml
- id: borrowed-device
  config:
    refs: ['DEEPSEEK_API_KEY']   # 额外要保护的凭据 ref 名
    shellHistoryOnWipe: false    # 清理时是否连 ~/.bash_history、PSReadLine 历史一起删
    autoArmOnNewMachine: true    # 新机器自动进入借用模式
```

## 在公用电脑上的完整流程

1. 装好 DSH 和本插件（插件本地目录安装即可）。
2. 首次启动自动进入借用模式 —— 顶栏出现，此时本机已有的数据全部记为"别人的"。
3. 填 API Key。填完后它就是磁盘上的一份明文，离开前会被「清理我的」删掉。
4. 正常干活。这之后产生的会话、附件、缓存都会记为你的。
5. 离开前点「清理我的」→ 确认，清单会先告诉你删哪些、不删哪些。
6. 退出 DSH；按需卸载 DSH、删掉安装包。
7. 到 platform.deepseek.com 吊销这个 key；浏览器里的历史 / 下载 / 站点数据用浏览器的"清除数据"再清一遍。

## 边界（重要）

- **先装插件，再开始聊天**。插件只能确认它"亲眼看到"创建的数据；装之前就已经存在的会话会被当作别人的，不会被清理。
- 如果你**续聊机主已有的会话**，那一条会话文件里混着两个人的内容，属于别人的文件，插件不会删——建议在别人的机器上只开新会话。
- 判断匿名的附件/缓存用创建时间，若机器文件系统不提供创建时间，会退化为修改时间，可能把机主最近碰过的文件误判成"你的"；此时请用 `/borrowed audit` 复核后再清理。
- 清理会删掉**你的**全部会话记录，无法恢复。
- 当前正在写入的会话日志如果被系统占用，会在**下次启动 DSH 时补删**（状态文件记录待删路径）。
- 浏览器侧数据、Windows 凭据管理器、你手动保存的文件都不在插件管辖内，最后一步要自己做。
- **没有"删掉磁盘副本还能继续用"的能力**：见上方"关于 API Key"，这是运行时的限制，不是没做。
